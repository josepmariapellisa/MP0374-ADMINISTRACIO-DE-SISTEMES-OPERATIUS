    Com està fet el sistema

    Visió general de l'arquitectura del sistema Ansible Web Manager.

    Vista de les parts del projecte

    El sistema Ansible Web Manager s'estructura en quatre capes principals: la interfície d'usuari al navegador, un backend desenvolupat amb Flask que gestiona la lògica de l'API, el motor d'Ansible Core que executa els playbooks i inventaris, i finalment els clients (Linux i Windows) que reben les ordres. La comunicació flueix des de l'usuari cap als clients a través del servidor central, garantint una gestió unificada i segura.

    El servidor (Flask)

    El servidor és el programa que "viu" a l'ordinador principal. S'encarrega de rebre les teves ordres quan prems un botó a la web i de passar-les a l'Ansible perquè les executi.

    L'aplicació app.py gestiona totes les peticions HTTP i coordina les operacions Ansible.

    El backend processa cada petició HTTP verificant primer l'autenticació de l'usuari. Si la petició és vàlida, es dirigeix a la funció run_ansible_adhoc, la qual selecciona el playbooks o mòdul necessari i l'executa contra l'inventari corresponent, retornant finalment el resultat en format JSON cap al navegador.

    La cara de la web (Frontend)

    És el que tu veus al navegador. Hem creat unes pàgines modernes i fàcils d'usar per gestionar els ordinadors sense haver d'escriure codi:

    • Panell principal: Per veure tots els ordinadors i instal·lar apps.
    • Pàgina d'inspecció: Per mirar què passa dins d'un ordinador concret.
    • Estils: Perquè la web es vegi bonica i neta.

    UI[Interfície Principal] --> HOSTS[Grid d'Hosts] UI --> APPS[Cataleg d'Apps] HOSTS --> ADD[Afegir Host Modal] HOSTS --> SCAN[Escaneig Xarxa Modal] HOSTS --> EXAM[Mode Examen Modal]

    webapp/ ├── app.py # Backend Flask ├── index.html # Panell principal ├── inspect.html # Inspecció de host ├── style.css # Estils ├── apps.json # Catàleg apps Linux ├── windows_apps.json # Catàleg apps Windows ├── users.json # Usuaris web ├── last_run.json # Última execució └── scan_results.json # Resultats escaneig

    
## Flux de Dades

### Instal·lació d'Apps

Quan l'usuari decideix aplicar canvis, la Web UI envia una petició POST al servidor Flask amb la llista d'aplicacions i hosts. El servidor actualitza els fitxers YAML dels playbooks dinàmicament i invoca el motor d'Ansible, que estableix connexions SSH paral·lels amb cada client per realitzar la instal·lació i retornar el resum d'estat a la interfície.

### Escaneig de Xarxa

L'escaneig de xarxa es basa en la detecció activa d'equips dins d'una subxarxa específica. El servidor realitza pings massius per comprovar la disponibilitat IP i posteriorment verifica l'estat del port 22. Els resultats es transmeten a la web UI, permetent a l'usuari seleccionar quins nous hosts vol incorporar permanentment al fitxer d'inventari del projecte.

## Modes d'Operació

### Mode Examen (iptables)

El Mode Examen utilitza iptables per aïllar els equips dels alumnes, permetent només el tràfic estrictament necessari cap a la LAN i serveis de gestió, mentre que el Control d'Entrada utilitza xinput per deshabilitar o habilitar els dispositius de teclat i ratolí de la sessió gràfica.


## Seguretat

### Autenticació Web

- Passwords hashejats amb SHA-256
- Decorador `@login_required` a rutes sensibles
- Sessions gestionades per Flask

### Connexió SSH

- Claus ed25519 sense password
- `StrictHostKeyChecking no` per automatització
- Usuari `ansible` separat amb sudo restringit

### Permisos Sudo

```bash
# /etc/sudoers.d/ansible
ansible ALL=(ALL) NOPASSWD:ALL

    Rendiment

    Paral·lelisme

    • Ansible executa en paral·lel per defecte (5 hosts)
    • Upload de fitxers amb subprocess paral·lel
    • Escaneig de xarxa amb Pool de processos

    Caché

    • Resultats d'escaneig guardats a scan_results.json
    • Classes guardades per recuperar ràpidament

    Optimitzacions

    • Ping timeout: 1 segon
    • SSH connect timeout: 3 segons
    • Reintents: 1 per defecte
