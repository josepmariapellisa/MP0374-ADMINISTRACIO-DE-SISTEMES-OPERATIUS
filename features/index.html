    Què pot fer aquest sistema

    Descripció detallada de totes les funcionalitats del sistema.

    El Mode Examen

    Serveix per bloquejar l'accés a Internet durant les proves perquè els alumnes no es puguin distreure o buscar respostes. Permet aplicar un mur virtual que només deixa oberta la connexió amb la xarxa del centre i el servidor.

    El Mode Examen és una funcionalitat crítica que permet als professors bloquejar l'accés a Internet de forma massiva. El sistema utilitza regles d'iptables per denegar tot el tràfic sortint cap als ports 80 i 443 (HTTP/HTTPS), mentre que manté obertes les rutes cap a la xarxa local (VLANs del centre) i el port 22 per garantir que la gestió via Ansible i SSH continuï funcionant correctament.

    Regles iptables (Activar)

    iptables -F OUTPUT                          # Neteja regles
iptables -A OUTPUT -p tcp --dport 22 -j ACCEPT           # SSH
iptables -A OUTPUT -d 192.168.0.0/16 -j ACCEPT          # Xarxa local
iptables -A OUTPUT -d 10.0.0.0/8 -j ACCEPT              # Xarxa privada A
iptables -A OUTPUT -d 172.16.0.0/12 -j ACCEPT           # Xarxa privada B
iptables -A OUTPUT -d 127.0.0.0/8 -j ACCEPT             # Localhost
iptables -A OUTPUT -p tcp --dport 80 -j REJECT --reject-with tcp-reset    # HTTP
iptables -A OUTPUT -p tcp --dport 443 -j REJECT --reject-with tcp-reset   # HTTPS

    Control de teclat i ratolí

    Aquesta eina permet "congelar" l'activitat dels alumnes deshabilitant els seus perifèrics d'entrada. És ideal per quan vols tota l'atenció de la classe a la pissarra.

    • Funcionament: El sistema identifica l'identificador (ID) del ratolí i el teclat a l'ordinador de l'alumne i li diu que deixi de rebre senyals.
    • Limitacions: Cal que l'altre ordinador tingui una sessió iniciada amb escriptori gràfic. No sol funcionar bé en ordinadors virtuals sense configuració extra.

    El control d'entrada permet captar l'atenció dels alumnes bloquejant els seus perifèrics. Mitjançant la utilitat xinput, el sistema identifica els identificadors (IDs) dels dispositius de teclat i ratolí de la sessió gràfica activa i els inhabilita temporalment. Una vegada el professor decideix alliberar el control, s'executa la comanda inversa per rehabilitar els drivers d'entrada sense necessitat de reiniciar la sessió.

    Dispositius Xinput

    ⎡ Virtual core pointer           id=2  [master pointer]
⎜   ↳ Virtual core XTEST pointer
⎜   ↳ xwayland-pointer
⎣ Virtual core keyboard          id=3  [master keyboard]
    ↳ Virtual core XTEST keyboard
    ↳ xwayland-keyboard

    id=2: Master pointer (controla tots els ratolins) id=3: Master keyboard (controla tots els teclats)

    Limitacions

    • Requereix sessió gràfica: Només funciona si hi ha un usuari loguejat amb X11/Wayland
    • No funciona en VMs sense dispositius d'entrada virtuals: VirtualBox, VMware necessiten configuració específica
    • Wayland: Funciona via Xwayland però pot tenir comportaments diferents

    Cerador d'ordinadors (Escaneig de xarxa)

    Aquesta funció ajuda a trobar els ordinadors de l'aula automàticament sense haver de saber l'adreça de cada un.

    • El procés: El servidor envia un "hola" (ping) a cada adreça possible de l'aula. Si algú respon, el sistema comprova si té la porta de control (SSH) oberta i si està preparat per rebre ordres.
    • Resultat: Et mostra una taula neta amb qui està a punt i qui no, per triar-los amb un clic.

    L'escaneig de xarxa és un procés de tres capes: primer es realitza un ping per detectar si la màquina està encesa, després es comprova si el port 22 (SSH) està obert i, finalment, s'intenta una connexió amb l'usuari ansible. Si totes les proves són positives, el host es marca com a "Ansible OK" i s'afegeix a la llista d'equips gestionables.

    Algorisme d'Escaneig

    for ip in range(1, 255):
    # 1. Ping test
    if ping(ip, timeout=1):
        # 2. SSH port check
        if ssh_connect(ip, user="ansible", timeout=3):
            status = "ansible_ok"
        else:
            status = "active_no_client"
    else:
        status = "inactive"

    Classes Guardades

    Els resultats d'escaneig es guarden per recuperar-los ràpidament:

  "203_20240312": {
    "subnet": "192.168.203.0/24",
    "hosts": [...],

}

    Bloqueig de programes instal·lats

    Aquesta funció serveix per impedir que els alumnes obrin certs programes que ja tenen a l'ordinador, com jocs o navegadors antics.

    • Mètode: El sistema els treu el "permís d'execució". És com si l'ordinador ja no recordés com s'ha d'obrir aquell programa fins que el professor el desbloquegi.
    • Categories: Pots triar bloquejar només els jocs de Steam, els navegadors de xarxa o eines com Discord.
    # Bloquejar
which steam | xargs chmod -x

# Desbloquejar
which steam | xargs chmod +x

    Comprovar Estat

    # Llistar paquets bloquejats
for pkg in $(dpkg -l | grep '^ii' | awk '{print $2}'); do
    bin=$(which $pkg 2>/dev/null || dpkg -L $pkg 2>/dev/null | grep -E '^/usr/(bin|sbin)/' | head -1)
    if [ -n "$bin" ] && [ ! -x "$bin" ]; then
        echo "$pkg"
    fi
done

    Enviament de fitxers

    Pots repartir exercicis o documents a tots els alumnes de cop sense necessitat de fer-ho un per un. El servidor puja el fitxer primer a la seva memòria i després l'envia a través del túnel segur a cada client.

    La transferència massiva es realitza de forma seqüencial però optimitzada. El fitxer es puja primer al servidor des del navegador del professor i després el sistema s'encarrega d'enviar-lo a cada host seleccionat utilitzant SCP (Secure Copy). El destí és /var/tmp/ per defecte a Linux, una ruta segura i accessible per a tots els usuaris que evita problemes de permisos.

    Destins

    Plataforma Destí
    Linux /var/tmp/
    Windows C:\ansible_temp\

    Comandes Remotes

    Execució de comandes ad-hoc en hosts.

    Funció run_ansible_adhoc

    def run_ansible_adhoc(hostname, module, args, ssh_user, platform):
    """Executa un mòdul Ansible en un host."""
    if platform == "linux":
        # Ansible module (shell, apt, etc.)
        ansible_module = module
    else:
        # Windows module (win_shell, win_package, etc.)
        ansible_module = f"ansible.windows.{module}"

    # Executa
    result = subprocess.run([
        "ansible", hostname,
        "-i", inventory_file,
        "-m", ansible_module,
        "-a", args,
        "-u", ssh_user
    ], capture_output=True)

    Exemples

    # Llistar paquets
ansible pc201 -m shell -a "dpkg -l" -u ansible

# Instal·lar app
ansible pc201 -m apt -a "name=vlc" -b

# Bloquejar web
ansible pc201 -m shell -a "echo '127.0.0.1 chatgpt.com >> /etc/hosts'" -b
