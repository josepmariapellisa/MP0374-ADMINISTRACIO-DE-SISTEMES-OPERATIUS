    Com parla la web amb el servidor: l'API

    Documentació completa de l'API REST d'Ansible Web Manager.

    Com funciona la comunicació

    L'API és com un missatger que porta les teves ordres des de la pàgina web fins al motor d'Ansible. Quan prems un botó:

    1. La web envia un missatge: Per exemple, "Instal·la el VLC al pc201".
    2. El servidor el rep: Comprova que tinguis permís per fer-ho.
    3. S'executa l'ordre: El servidor parla amb Ansible i aquest amb l'ordinador de l'alumne.
    4. Rep el resultat: El missatger torna a la web per dir-te si tot ha anat bé.
    %%{init: {'theme': 'neutral'}}%%
sequenceDiagram
    participant P as Professor (Navegador)
    participant W as Web (Flask)
    participant A as Ansible
    participant C as Alumne (Client)

    P->>W: Selecciona acció (ex: botó "Aplicar")
    W->>W: Valida permissos i prepara dades
    W->>A: Llança motor d'Ansible
    A->>C: Connecta't i executa tasca (SSH/WinRM)
    C-->>A: Retorna resultat de la tasca
    A-->>W: Retorna estat final
    W-->>P: Mostra confirmació a la pantalla

    Autenticació

    POST /login

    Inicia sessió a l'aplicació web.

    Request

    POST /login HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=profe&password=profe

    Response (200 OK)

    {
  "success": true,
  "redirect": "/"
}

    Response (401 Unauthorized)

    {
  "success": false,
  "message": "Credencials incorrectes"
}

    Camps

    Camp Tipus Requisit Descripció
    username string Sí Nom d'usuari
    password string Sí Contrasenya (plain text)

    Usuaris per Defecte

    Usuari Contrasenya Rol
    profe profe admin

    GET /logout

    Tanca la sessió de l'usuari.

    Response (302 Found)

    Redirigeix a /login.

    Gestió d'aplicacions

    Aquesta part serveix per enviar ordres d'instal·lació. El procés és el següent: la web envia la llista de programes, el servidor prepara un fitxer anomenat apps.yml amb aquestes apps i l'Ansible s'encarrega d'instal·lar-les als ordinadors que hagis triat.

    Request

    POST /apply HTTP/1.1
Content-Type: application/x-www-form-urlencoded

platform=linux&apps=vlc,firefox,gimp&hosts=pc201,pc202

    Response (200 OK)

    {
  "success": true,
  "results": {
    "pc201": {
      "changed": true,
      "installed": ["vlc", "firefox"],
      "failed": []
    },
    "pc202": {
      "changed": false,
      "installed": [],
      "failed": []
    }
  },
  "summary": {
    "total": 2,
    "changed": 1,
    "failed": 0
  }
}

    Camps

    Camp Tipus Descripció
    platform string linux o windows
    apps string Llista d'apps separades per comes
    hosts string Llista d'hosts separades per comes

    Errors

    Codi Descripció
    no_apps_selected Cap app seleccionada
    no_hosts_selected Cap host seleccionat
    playbook_failed Error executant playbook

    POST /apps/catalog

    Actualitza el catàleg d'apps des de GitHub.

    Request

    POST /apps/catalog HTTP/1.1

    Response (200 OK)

    {
  "success": true,
  "apps": {
    "vlc": {
      "name": "VLC Media Player",
      "description": "Reproductor multimèdia",
      "category": "multimedia",
      "package": "vlc"
    }
  },
  "updated_at": "2024-03-12T10:30:00"
}

    Gestió d'Hosts

    POST /hosts/add

    Afegeix un nou host a l'inventari.

    Request

    POST /hosts/add HTTP/1.1
Content-Type: application/x-www-form-urlencoded

hostname=pc203&ip=192.168.203.203&platform=linux

    Response (200 OK)

    {
  "success": true,
  "message": "Host pc203 afegit correctament",
  "host": {
    "name": "pc203",
    "ip": "192.168.203.203",
    "platform": "linux"
  }
}

    Camps

    Camp Tipus Requisit Descripció
    hostname string Sí Nom del host (alphanumeric)
    ip string Sí Adreça IP
    platform string Sí linux o windows

    Validacions

    • hostname: Només lletres, números, guions. Màx 50 caràcters.
    • ip: Format IPv4 vàlid (xxx.xxx.xxx.xxx)

    Errors

    Codi Descripció
    invalid_hostname Nom de host invàlid
    invalid_ip Adreça IP invàlida
    host_exists El host ja existeix

    Elimina un host de l'inventari.

    Request

    POST /hosts/remove HTTP/1.1
Content-Type: application/x-www-form-urlencoded

hostname=pc203&platform=linux

    Response (200 OK)

    {
  "success": true,
  "message": "Host pc203 eliminat"
}

    Escaneig de Xarxa

    POST /api/scan

    Escaneja una subxarxa per descobrir hosts actius.

    Request

    POST /api/scan HTTP/1.1
Content-Type: application/x-www-form-urlencoded

subnet=192.168.203.0/24&platform=linux

    Response (200 OK)

    {
  "success": true,
  "hosts": [
    {
      "ip": "192.168.203.201",
      "hostname": "pc201",
      "status": "ansible_ok"
    },
    {
      "ip": "192.168.203.202",
      "hostname": "pc202.iesebre.local",
      "status": "active_no_client"
    },
    {
      "ip": "192.168.203.203",
      "hostname": null,
      "status": "inactive"
    }
  ],
  "scanned": 254,
  "active": 2,
  "ansible_ready": 1
}

    Camps

    Camp Tipus Descripció
    subnet string Subxarxa en format CIDR (ex: 192.168.203.0/24)
    platform string linux o windows

    Estats d'Host

    Estat Icon Descripció
    ansible_ok OK SSH funciona amb usuari ansible
    active_no_client Alerta Ping respon però no SSH o usuari ansible no existeix
    inactive Inactiu No respon al ping

    Afegeix múltiples hosts a l'inventari d'un cop.

    Response (200 OK)

    {
  "success": true,
  "added": 2,
  "skipped": 0,
  "total": 2
}

    El Mode Examen

    Quan actives aquest mode, el servidor envia unes regles de seguretat (anomenades iptables) a l'ordinador de l'alumne. Aquestes regles fan que l'ordinador ignori qualsevol petició per entrar a Internet, però permeten que segueixi parlant amb el servidor del centre.

    POST /api/pc201/exam_mode HTTP/1.1
Content-Type: application/x-www-form-urlencoded

enable=true&ssh_user=ansible

    Quan enable=true: S'executen aquestes regles iptables

    iptables -F OUTPUT
iptables -A OUTPUT -p tcp --dport 22 -j ACCEPT           # SSH
iptables -A OUTPUT -d 192.168.0.0/16 -j ACCEPT          # LAN
iptables -A OUTPUT -d 10.0.0.0/8 -j ACCEPT              # Private A
iptables -A OUTPUT -d 172.16.0.0/12 -j ACCEPT           # Private B
iptables -A OUTPUT -d 127.0.0.0/8 -j ACCEPT             # Localhost
iptables -A OUTPUT -p tcp --dport 80 -j REJECT --reject-with tcp-reset    # HTTP
iptables -A OUTPUT -p tcp --dport 443 -j REJECT --reject-with tcp-reset   # HTTPS

    Desactivar Mode Examen

    POST /api/pc201/exam_mode HTTP/1.1
Content-Type: application/x-www-form-urlencoded

enable=false&ssh_user=ansible

    Quan enable=false: S'executen aquestes ordres

    iptables -F OUTPUT
iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -j ACCEPT
sed -i '/### IES_DE_EBRE_BLOCKED ###/,/### END_BLOCKED ###/d' /etc/hosts
systemctl restart systemd-resolved

    Response (200 OK)

    {
  "success": true,
  "message": "Mode Examen activat - Totes les webs bloquejades",
  "mode": "exam"
}

    Control d'Entrada

    POST /api//input_control

    Bloqueja o desbloqueja teclat i ratolí.

    Bloquejar Entrada

    POST /api/pc201/input_control HTTP/1.1
Content-Type: application/x-www-form-urlencoded

enable=true&ssh_user=ansible

    S'executa:

    # Trobar usuari actiu
ACTIVE_USER=$(who | grep -E 'tty|:[0-9]' | head -1 | awk '{print $1}')

# Desactiva master devices
sudo -u "$ACTIVE_USER" DISPLAY=:0 xinput disable 2  # Master pointer
sudo -u "$ACTIVE_USER" DISPLAY=:0 xinput disable 3  # Master keyboard

    Desbloquejar Entrada

    POST /api/pc201/input_control HTTP/1.1
Content-Type: application/x-www-form-urlencoded

enable=false&ssh_user=ansible

    S'executa:

    sudo -u "$ACTIVE_USER" DISPLAY=:0 xinput enable 2
sudo -u "$ACTIVE_USER" DISPLAY=:0 xinput enable 3

    Response (200 OK)

    {
  "success": true,
  "message": "Teclat i ratolí bloquejats - Els alumnes no poden interactuar"
}

    Dispositius Xinput

    ⎡ Virtual core pointer           id=2  [master pointer (3)]
⎣ Virtual core keyboard          id=3  [master keyboard (2)]
    ID Tipus Descripció
    2 Master pointer Controla tots els ratolins
    3 Master keyboard Controla tots els teclats

    Bloqueja l'execució d'un programa usant chmod -x.

    POST /inspect/pc201/block_package HTTP/1.1
Content-Type: application/x-www-form-urlencoded

package=steam&ssh_user=ansible

    S'executa:

    which steam | xargs chmod -x

    Response (200 OK)

    {
  "success": true,
  "message": "Programa steam bloquejat"
}

Content-Type: application/x-www-form-urlencoded

package=steam&ssh_user=ansible

    S'executa:

    which steam | xargs chmod +x

    Response (200 OK)

    {
  "success": true,
  "message": "Programa steam desbloquejat"
}

    Bloqueig de Webs

    POST /api//block_websites

    Bloqueja l'accés a llocs web via /etc/hosts.

    Request

    POST /api/pc201/block_websites HTTP/1.1
Content-Type: application/x-www-form-urlencoded

websites=marca.com,elpais.com&categories=ai,social&ssh_user=ansible

    S'executa:

    # Afegeix a /etc/hosts
### IES_DE_EBRE_BLOCKED ###
127.0.0.1 marca.com
127.0.0.1 www.marca.com
127.0.0.1 chatgpt.com
127.0.0.1 www.chatgpt.com
### END_BLOCKED ###

    Response (200 OK)

    {
  "success": true,
  "message": "Blocats 10 llocs webs",
  "count": 10
}

    Categories Disponibles

    Categoria ID Llocs d'exemple
    IA ai chatgpt.com, claude.ai, gemini.google.com
    Social social facebook.com, twitter.com, discord.com
    Gaming gaming steam.com, epicgames.com, roblox.com
    Streaming streaming youtube.com, twitch.tv, netflix.com

    POST /api//unblock_websites

    Desbloqueja llocs web.

    Request

    POST /api/pc201/unblock_websites HTTP/1.1
Content-Type: application/x-www-form-urlencoded

all=true&ssh_user=ansible

    S'executa:

    iptables -F OUTPUT
iptables -A OUTPUT -j ACCEPT
sed -i '/### IES_DE_EBRE_BLOCKED ###/,/### END_BLOCKED ###/d' /etc/hosts
systemctl restart systemd-resolved

    Response (200 OK)

    {
  "success": true,
  "message": "Tots els llocs webs desbloquejats - iptables netejats"
}

    GET /api//blocked_websites

    Obté la llista de webs bloquejades.

    GET /api/pc201/blocked_websites?ssh_user=ansible HTTP/1.1

    Response (200 OK)

    {

    Transferència de Fitxers

    El procés de transferència s'encarrega de rebre el fitxer al servidor Flask, desar-lo temporalment i després distribuir-lo paral·lelament a tots els hosts seleccionats mitjançant ordres SCP. Una vegada completada la transferència a cada host, el servidor retorna un resum detallat amb l'estat final de cada enviament.

    Request

    POST /upload_multi HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary

------WebKitFormBoundary
Content-Disposition: form-data; name="file"; filename="examen.pdf"
Content-Type: application/pdf

<BINARY DATA>
------WebKitFormBoundary
Content-Disposition: form-data; name="hosts"

pc201,pc202,pc203
------WebKitFormBoundary
Content-Disposition: form-data; name="ssh_user"

ansible
------WebKitFormBoundary
Content-Disposition: form-data; name="platform"

linux
------WebKitFormBoundary--

    Response (200 OK)

    {
  "success": true,
  "message": "Fitxer pujat a 3 hosts",
  "file": "examen.pdf",
  "hosts": ["pc201", "pc202", "pc203"],
  "destination": "/var/tmp/"
}

    Camps

    Camp Tipus Descripció
    file file Fitxer a pujar
    hosts string Llista d'hosts separats per comes
    ssh_user string Usuari SSH (default: ansible)
    platform string linux o windows

    Destins

    Plataforma Destí
    Linux /var/tmp/
    Windows C:\ansible_temp\

    Codis d'Error

    Format d'Error

    {
  "success": false,
  "message": "Descripció de l'error",
  "error_code": "ERROR_CODE"
}

    Llista de Codis d'Error

    Codi HTTP Descripció
    AUTH_REQUIRED 401 Cal autenticació
    INVALID_CREDENTIALS 401 Credencials incorrectes
    PERMISSION_DENIED 403 Permisos insuficients
    HOST_NOT_FOUND 404 Host no trobat
    INVALID_HOSTNAME 400 Nom de host invàlid
    INVALID_IP 400 Adreça IP invàlida
    HOST_EXISTS 400 El host ja existeix
    NO_APPS_SELECTED 400 Cap app seleccionada
    NO_HOSTS_SELECTED 400 Cap host seleccionat
    PLAYBOOK_FAILED 500 Error executant playbook
    SHELL_COMMAND_FAILED 500 Error executant comanda
    NETWORK_SCAN_FAILED 500 Error escanejant xarxa
    FILE_NOT_FOUND 404 Fitxer no trobat
    UPLOAD_FAILED 500 Error pujant fitxer
    USER_EXISTS 400 L'usuari ja existeix
    USER_NOT_FOUND 404 Usuari no trobat

    Rate Limiting

    Per prevenir abusos, l'API té els següents límits:

    Tipus Límit Període
    Login 5 intents 5 minuts
    Escaneig de xarxa 3 peticions 10 minuts
    Peticions generals 100 peticions 1 minut

    Quan s'excedeix el límit:

    {
  "success": false,
  "message": "Massa peticions. Torna-ho a intentar més tard.",
  "error_code": "RATE_LIMIT_EXCEEDED",
  "retry_after": 60
}

    curl -b cookies.txt -X POST http://localhost:8080/api/pc201/exam_mode \
  -d "enable=true&ssh_user=ansible"

    Afegir Host

    curl -b cookies.txt -X POST http://localhost:8080/hosts/add \
  -d "hostname=pc204&ip=192.168.203.204&platform=linux"
