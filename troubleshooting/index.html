    Què fer si alguna cosa no funciona

    Guia de resolució de problemes comuns.

    Problemari

    Aquesta guia està organitzada per categories de problemes: primer abordem els fallos de connexió (que solen ser el 90% dels casos), després analitzem problemes amb funcions específiques com el Mode Examen o la instal·lació d'apps, i finalment donem consells per millorar el rendiment i la velocitat del sistema.

    Problemes de connexió amb Linux

    Si el servidor no pot parlar amb els ordinadors Linux (Ubuntu), el més habitual és que hi hagi un problema amb la clau de seguretat o que el servei SSH estigui apagat.

    • Error de clau (Permission denied): Això vol dir que l'ordinador de l'alumne no reconeix la clau del servidor. Pots provar de tornar a executar l'script d'instal·lació del client o comprovar si la clau del servidor encara és la mateixa.
    • Ordinador no trobat (Connection refused): Segurament el servei de comunicació (SSH) està apagat. Entra a l'ordinador de l'alumne i activa'l amb la comanda sudo systemctl start ssh.
    • Error d'identitat (Host key verification failed): Això passa si has canviat l'ordinador però mantens la mateixa IP. Esborra la memòria de l'ordinador antic amb ssh-keygen -R <IP>.

    Símptomes:

    The authenticity of host '192.168.203.201' can't be established.
ECDSA key fingerprint is ...

    Solucions:

    1. Elimina la clau antiga:
    ssh-keygen -R 192.168.203.201
    1. O desactiva la verificació (no recomanat):
    # A ~/.ssh/config
Host *
    StrictHostKeyChecking no

    Problemes de connexió amb Windows

    Perquè el servidor pugui parlar amb Windows, necessitem que el servei WinRM estigui ben configurat i que l'usuari tingui permisos d'administrador.

    • Error de mòdul (No module named winrm): El servidor necessita una eina extra per parlar amb Windows. Carda pip3 install pywinrm al servidor per solucionar-ho.
    • Accés denegat (401 Unauthorized): Revisa que l'usuari i la contrasenya siguin correctes al fitxer d'inventari del servidor. Sol ser Ansible123!.
    • Problema de Firewall: Windows pot estar bloquejant el pas. Revisa que les regles que crea l'script d'instal·lació estiguin actives.

    Problemes de Funcionalitat

    Mode Examen: "La web encara funciona"

    Símptomes: Després d'activar el Mode Examen, els alumnes encara poden navegar.

    Solucions:

    1. Verifica les regles iptables:
    # Al client
ansible pc201 -m shell -a "sudo iptables -L OUTPUT -n" -u ansible
    1. Comprova si hi ha regles conflictives:
    # Pot haver-hi altres regles que permeten el tràfic
ansible pc201 -m shell -a "sudo iptables -F" -u ansible
# Després reactiva el Mode Examen
    1. Verifica que no estan usant VPN o proxy:
    # Si usen una VPN, el tràfic pot sortir per la VPN
ansible pc201 -m shell -a "ps aux | grep vpn" -u ansible

    Mode Examen: "No es pot desactivar"

    Símptomes: Després de desactivar el Mode Examen, la web encara no funciona.

    Solucions:

    1. Verifica que les regles s'han netejat:
    # Al client
ansible pc201 -m shell -a "sudo iptables -L OUTPUT -n" -u ansible
# Ha de mostrar ACCEPT per defecte
    1. Neteja manualment les regles:
    ansible pc201 -m shell -a "sudo iptables -F OUTPUT && sudo iptables -A OUTPUT -j ACCEPT" -u ansible
    1. Verifica /etc/hosts:
    # Si hi ha entrades bloquejades, elimina-les
ansible pc201 -m shell -a "sudo grep -v '# BLOCKED_IES' /etc/hosts > /tmp/hosts && sudo mv /tmp/hosts /etc/hosts" -u ansible

    Control d'Entrada: "Encara poden escriure"

    Símptomes: Després de bloquejar l'entrada, els alumnes encara poden escriure.

    Solucions:

    1. Verifica que hi ha sessió gràfica:
    # Al client
who
# Ha de mostrar un usuari amb tty o display :0
    1. Verifica els dispositius xinput:
    # Al client
xinput list
# Ha de mostrar Virtual core pointer i Virtual core keyboard
    1. Prova manualment:
    # Al client
sudo -u alumne DISPLAY=:0 xinput disable 2
# Prova escriure - ha de fallar
    1. Comprova si és Wayland:
    # Si veus "Xwayland", potser no funciona correctament
echo $XDG_SESSION_TYPE

    Nota: El control d'entrada pot no funcionar correctament en VMs com VirtualBox o VMware.

    Apps: "No s'instal·len"

    Símptomes: Les apps seleccionades no s'instal·len correctament.

    Solucions:

    1. Verifica que el repositori està actualitzat:
    ansible pc201 -m apt -a "update_cache=yes" -b
    1. Verifica que el paquet existeix:
    ansible pc201 -m shell -a "apt-cache search vlc" -u ansible
    1. Prova instal·lar manualment:
    ansible pc201 -m apt -a "name=vlc state=present" -b
    1. Comprova l'espai de disc:
    ansible pc201 -m shell -a "df -h" -u ansible

    Apps: "No es desinstal·len"

    Símptomes: Les apps no s'eliminen correctament.

    Solucions:

    1. Verifica que el paquet està instal·lat:
    ansible pc201 -m shell -a "dpkg -l | grep vlc" -u ansible
    1. Prova desinstal·lar manualment:
    ansible pc201 -m apt -a "name=vlc state=absent purge=yes" -b
    1. Comprova si hi ha dependències:
    ansible pc201 -m shell -a "apt-get remove vlc --dry-run" -u ansible

    Problemes de Rendiment

    Escaneig: "Molt lent"

    Símptomes: L'escaneig de xarxa tarda massa.

    Solucions:

    1. Redueix el rang d'escaneig:
    # En lloc d'escanejar tota la /24, escaneja només un rang
SCAN_RANGE = range(1, 100)  # Només 1-99 en lloc de 1-254
    1. Redueix el timeout:
    ping -c 1 -W 0.5  # En lloc de -W 1
    1. Usa nmap en lloc de ping (més ràpid):
    nmap -sn 192.168.203.1-254 -T4

    Timeouts: "Connection timeout"

    Símptomes: Les operacions Ansible fan timeout.

    Solucions:

    1. Augmenta el timeout d'Ansible:
    # A ansible.cfg
[defaults]
timeout = 30
    1. Augmenta el timeout SSH:
    # A ~/.ssh/config
Host *
    ConnectTimeout 10
    ServerAliveInterval 5
    1. Redueix el nombre d'hosts paral·lels:
    # A ansible.cfg
[defaults]
forks = 3  # En lloc de 5

    Problemes Web

    Login: "Credencials incorrectes"

    Símptomes: No es pot iniciar sessió a la web.

    Solucions:

    1. Restaura les credencials per defecte:
    rm ~/ansible_project/webapp/users.json
# Reinicia l'app - es crearan l'usuari profe/profe
    1. Crea un usuari nou via Python:
    import json
import hashlib

users = {
    "profe": {
        "password": hashlib.sha256("profe".encode()).hexdigest(),
        "role": "admin",
        "created_at": "2024-03-12"
    }
}

with open("users.json", "w") as f:
    json.dump(users, f)

    Web: "Pàgina en blanc"

    Símptomes: La web carrega però es veu en blanc.

    Solucions:

    1. Verifica que Flask està executant-se:
    ps aux | grep app.py
    1. Comprova els logs:
    python3 app.py
# Mira els errors a la terminal
    1. Verifica el port:
    lsof -i :8080
    1. Prova amb mode debug:
    if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8080, debug=True)
