    Projecte de Gestió Centralitzada amb Ansible, Flask i Clients Heterogenis

    Introducció

    En el món de les infraestructures informàtiques actuals, la diversitat de sistemes operatius en una mateixa xarxa és una realitat quotidiana. La gestió manual de múltiples equips, especialment quan treballem amb plataformes heterogènies com Ubuntu i Windows, pot esdevenir una tasca complexa, propensa a errors i poc eficient.

    Davant aquest repte, neix el nostre projecte: una solució de gestió centralitzada que combina el poder d'Ansible com a eina d'automatització, amb la flexibilitat d'un frontal web desenvolupat amb Flask. L'objectiu principal és crear un sistema unificat que permeti administrar de manera senzilla i intuïtiva tant clients Linux (Ubuntu) com Windows, des d'una única interfície.

    El projecte s'ha desenvolupat seguint un enfocament progressiu i metodològic, dividit en tres fases clarament diferenciades:

    Primera Fase: Implementació amb Client Ubuntu

    En aquesta etapa inicial, vam establir les bases del projecte configurant un servidor Ubuntu com a node de control d'Ansible. Vam dissenyar els primers playbooks per gestionar un client Ubuntu, automatitzant tasques com la instal·lació de programari, la configuració del sistema i la gestió d'usuaris. Aquesta fase ens va permetre validar l'arquitectura bàsica i familiaritzar-nos amb el funcionament d'Ansible en un entorn natiu.

    Segona Fase: Expansió a Client Windows

    Un cop consolidada la gestió sobre Ubuntu, vam abordar el repte d'integrar un client Windows a la nostra infraestructura. Aquesta fase va requerir una configuració específica per superar les diferències inherents entre sistemes, incloent l'ús de WinRM (Windows Remote Management) com a protocol de connexió alternatiu a SSH. Vam adaptar els nostres playbooks i vam crear nous mòduls específics per a Windows, demostrant la versatilitat d'Ansible per operar en entorns heterogenis.

    Tercera Fase: Desenvolupament del Frontend amb Flask

    Finalment, vam desenvolupar una interfície web intuïtiva utilitzant Flask per democratitzar l'accés a les funcionalitats d'Ansible. Aquest frontal permet als usuaris, independentment del seu coneixement tècnic sobre Ansible, executar playbooks, visualitzar l'estat dels clients i gestionar les tasques més comunes des d'un entorn gràfic amigable. La integració entre Flask i Ansible es realitza mitjançant crides al sistema o l'ús de l'API d'Ansible, oferint una experiència d'usuari fluida i eficient.

    Objectius del Projecte

    • Automatització Centralitzada: Crear un punt únic de gestió per a clients amb diferents sistemes operatius.
    • Accessibilitat: Proporcionar una interfície web intuïtiva que simplifiqui les tasques administratives.
    • Escalabilitat: Dissenyar una solució que permeti afegir nous clients amb facilitat, independentment de la seva plataforma.
    • Documentació i Reproducibilitat: Establir una base sòlida de coneixement que permeti replicar el projecte en altres entorns.

    Aquest document recull el procés complet de desenvolupament, les decisions tècniques adoptades i els resultats obtinguts, amb l'objectiu de servir com a guia i referència per a futures implementacions similars.

    PRÒCES DE CONFIGURACIÓ

    Instalem el paquet openssh-server al client Ubuntu per permetre la connexió remota. Aquest pas és necessari perquè Ansible pugui gestionar el client a través de SSH.

    Configurem el tallafocs UFW per permetre les connexions SSH entrants. Aquesta regla garanteix que el servidor Ansible pugui comunicar-se correctament amb el client Ubuntu.

    Habilitem el servei SSH perquè s'iniciï automàticament en cada reinici del sistema. D'aquesta manera, assegurem que el client Ubuntu estigui sempre accessible per al servidor Ansible.

    Verifiquem que Python 3 estigui instal·lat al client Ubuntu, ja que és un requisit necessari per al funcionament d'Ansible. El sistema confirma que disposem de la versió 3.10.12, compatible amb les nostres necessitats.

    Creem l'usuari "ansible" al servidor Ubuntu per gestionar les connexions amb els clients. Observem un avís sobre la seguretat de la contrasenya, però continuem amb el procés de creació.

    Afegim l'usuari "ansible" al fitxer sudoers per permetre-li executar comandes amb privilegis administratius sense contrasenya. Aquesta configuració és necessària perquè Ansible pugui gestionar el servidor de forma automatitzada.

    Modifiquem el fitxer de configuració SSH al client Ubuntu per reforçar la seguretat. Deshabilitem l'autenticació per contrasenya i l'accés root, i habilitem l'autenticació per clau pública, preparant el sistema per a connexions segures des d'Ansible.

    Comprovem que el servei SSH està actiu i funcionant correctament al client Ubuntu. Confirmem que està habilitat per iniciar-se automàticament i que ha carregat sense errors, garantint la connectivitat remota.

    Iniciem la instal·lació d'Ansible al client Ubuntu per preparar-lo com a node de control. El sistema mostra totes les dependències necessàries que s'instal·laran juntament amb Ansible.

    Comprovem que Ansible s'ha instal·lat correctament al client Ubuntu. El sistema confirma la versió de Python associada, assegurant que tot està preparat per començar a treballar.

    Generem un parell de claus SSH amb l'algoritme ed25519 per a les connexions segures d'Ansible. La clau privada es guarda amb el nom "ansible_lab" i s'utilitzarà per autenticar-se als clients sense contrasenya.

    Establim els permisos adequats (600) per a la clau privada d'Ansible. Aquesta configuració de seguretat és necessària perquè SSH accepti utilitzar la clau per a les connexions.

    Desarem la copia de la clau Publica al client per tenir una confiança entre ells correctament i no haber de iniciar sessio

    Creem l'estructura de carpetes necessària per organitzar el projecte Ansible. Generem els directoris per als playbooks i les variables de grup per mantenir una jerarquia clara i ordenada.

    Creem el fitxer d'inventari d'Ansible definint el servidor "lamp" amb la seva IP i variables de connexió. Especifiquem l'usuari ansible, la clau privada i l'intèrpret de Python per a una gestió correcta.

    Creem un playbook d'Ansible per assegurar que els serveis Apache i MySQL estiguin actius. També afegim una tasca per instal·lar Telegram Desktop, demostrant la gestió de paquets i serveis.

    Executem un ping d'Ansible per verificar la connectivitat amb el servidor "lamp". La resposta "pong" confirma que la connexió SSH funciona correctament amb la clau privada configurada.

    CLIENT WINDOWS

    Iniciem la instal·lació d'OpenSSH al client Windows per habilitar la gestió remota. Aquest component permetrà que Ansible es connecti mitjançant SSH en lloc de WinRM, simplificant la configuració.

    Comprovem que el servei SSHd està actiu al client Windows. El sistema confirma que el servei està en execució, preparat per rebre connexions remotes des del servidor Ansible.

    Afegim una regla al tallafocs de Windows per permetre connexions entrants pel port 22 (SSH). Aquesta configuració és necessària perquè el servidor Ansible pugui accedir al client Windows de forma remota.

    Configurem el servei SSH perquè s'iniciï automàticament en cada reinici del sistema Windows. Assegurem així que el client estigui sempre accessible per al servidor Ansible.

    Establim PowerShell com a shell per defecte per a les connexions SSH a Windows. Aquesta configuració al registre del sistema assegura que Ansible pugui executar comandes correctament en connectar-se al client Windows.

    Iniciem el servei SSH manualment al client Windows per posar-lo en funcionament immediatament. D'aquesta manera activem la connectivitat remota sense necessitat de reiniciar el sistema.

    Realitzem una connexió SSH des del servidor Ubuntu al client Windows per verificar la connectivitat. Acceptem la clau del host per establir la connexió per primera vegada.

    Confirmem que la connexió SSH des del servidor Ubuntu al client Windows s'ha realitzat correctament. El terminal mostra el prompt de Windows, indicant que la comunicació remota funciona perfectament.

    Intentem connectar-nos al client Windows utilitzant l'usuari local "pellisa". El sistema sol·licita la contrasenya per completar l'autenticació.

    Afegim el client Windows a l'inventari d'Ansible amb les variables de connexió específiques. Configurem el tipus de shell com a PowerShell i desactivem la comprovació estricta de claus per facilitar la connexió.

    Instal·lem l'eina sshpass al servidor Ubuntu per permetre l'autenticació amb contrasenya en les connexions SSH. Aquest paquet serà útil per connectar-nos al client Windows mentre no tinguem configurada l'autenticació per clau pública.

    Comentem temporalment la configuració del servidor Ubuntu i deixem actiu només el client Windows. Ajustem les variables per utilitzar l'usuari "pellisa" amb connexió SSH i shell PowerShell.

    Executem el mòdul win_ping per verificar la connectivitat d'Ansible amb el client Windows. La resposta "pong" confirma que Ansible pot comunicar-se correctament amb Windows mitjançant SSH i autenticació per contrasenya.

    Generem un nou parell de claus RSA de 4096 bits per configurar l'autenticació sense contrasenya amb el client Windows. Aquest pas millorarà la seguretat i facilitarà les connexions automatitzades d'Ansible.

    Creem el directori i el fitxer per a les claus autoritzades d'administradors a Windows. Aquest fitxer permetrà configurar l'autenticació per clau pública per a les connexions SSH.

    Afegim la clau pública generada al servidor Ubuntu al fitxer d'autorització de Windows. Aquest pas completa la configuració per permetre l'autenticació SSH per clau pública sense contrasenya.

    Mostrem el contingut de la clau privada RSA generada al servidor Ubuntu per verificar-ne la creació. Aquesta clau s'utilitzarà per autenticar-se al client Windows sense necessitat de contrasenya.

    Configurem els permisos del fitxer de claus autoritzades per garantir que només els usuaris amb privilegis hi puguin accedir. Observem un error en assignar permisos a Administradors, que caldrà resoldre per completar la configuració.

    Editem el fitxer de configuració SSH a Windows per especificar la ubicació del fitxer de claus autoritzades per al grup d'administradors. Aquesta directiva permetrà l'autenticació per clau pública per als usuaris administradors.

    Generem un nou parell de claus ed25519 sense frase de contrasenya per simplificar l'autenticació automatitzada. Mostrem la clau pública que haurem de copiar al client Windows per completar la configuració.

    Afegim la nova clau pública ed25519 al fitxer de claus autoritzades de Windows mitjançant PowerShell. Aquesta configuració permetrà l'autenticació SSH sense contrasenya des del servidor Ubuntu.

    Executem el mòdul win_ping d'Ansible i obtenim una resposta "pong" sense necessitat d'introduir contrasenya. Confirmem que l'autenticació per clau pública funciona correctament amb el client Windows.

    Instal·lem la col·lecció de Chocolatey per a Ansible per ampliar les capacitats de gestió de paquets a Windows. Aquesta col·lecció permetrà instal·lar programari de manera més eficient als clients Windows.
