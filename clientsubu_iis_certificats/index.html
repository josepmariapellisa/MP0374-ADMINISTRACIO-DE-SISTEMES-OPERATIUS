    Pràctica 5

    Introducció i Context

    Aquesta pràctica de 2n d'ASIX integra diverses tecnologies Microsoft i Linux per crear una infraestructura corporativa completa. Partint d'un escenari real empresarial, hem implementat un entorn mixt on un Windows Server 2025 gestiona el domini corporatiu amb Active Directory, mentre un client Ubuntu 22.04 s'uneix al domini per accedir als recursos compartits. La pràctica combina administració de sistemes, xarxes i seguretat, simulant un entorn de producció amb servidors Windows i clients Linux típic d'empreses actuals.

    Arquitectura de la Pràctica

    El disseny de la pràctica segueix una estructura lògica en tres capes: infraestructura de xarxa, serveis de directori i autenticació, i serveis d'aplicació. A la capa de xarxa, configurem dues interfícies al servidor: una LAN interna (192.168.2.101/24) que simula la xarxa corporativa i una interfície externa (10.10.1.1) per a connexions VPN. El client Ubuntu es connecta mitjançant VPN obtenint una adreça del pool 172.16.0.0-172.16.0.10.

    A la capa de serveis de directori, implementem Active Directory Domain Services creant el domini josep.lan amb una estructura organitzativa que inclou usuaris, grups i equips. Configurem polítiques de grup bàsiques i recursos compartits amb permisos NTFS. A la capa d'aplicació, instal·lem Internet Information Services (IIS) per allotjar un lloc web intranet i implementem Servicios de Certificados de Active Directory per crear una PKI corporativa amb certificats SSL.

    Fases d'Implementació

    1. Configuració del Domini Windows La primera fase inclou la instal·lació i configuració de Windows Server 2025 com a controlador de domini. Creem el bosc josep.lan amb nivell funcional Windows Server 2025, configurem DNS integrats i implementem estructures OU per organitzar usuaris i equips. Creem usuaris com josep pellisa i configurem permisos granulars als recursos compartits.

    2. Integració del Client Linux La segona fase se centra en la integració del client Ubuntu al domini Windows. Instal·lem paquets com realmd, sssd, samba i krb5-user per permetre l'autenticació contra Active Directory. Configurem DNS i Kerberos per a la resolució de noms i autenticació, i unim el client al domini utilitzant credencials d'administrador. Verifiquem que els usuaris del domini poden iniciar sessió al client Linux.

    3. Implementació de Serveis Web A la tercera fase, instal·lem IIS al servidor Windows i creem un lloc web intranet anomenat "INTRANET JOSEP PELLISA". Desenvolupem una pàgina HTML personalitzada amb recursos corporatius i configurem les opcions del servidor web per a un funcionament òptim. Configurem DNS per resoldre josep.lan a l'adreça IP del servidor.

    4. Seguretat amb Certificats SSL La quarta fase implementa seguretat mitjançant certificats SSL. Creem una entitat de certificació arrel empresarial josep-SERVER25-CA amb clau RSA 4096 i SHA256. Configurem el lloc web IIS per utilitzar HTTPS al port 443 i assignem el certificat SSL per a connexions xifrades. Instal·lem el certificat arrel als clients per establir confiança.

    Estem canviant el nom del host del client Ubuntu per identificar-lo clarament dins de la xarxa del domini Windows Server, editem el fitxer /etc/hostname i posem ubuntujp com a nom del sistema per a la seva integració al domini.

    Comprovem la connectivitat amb el servidor Windows fent ping a la seva IP 192.168.2.101 des del client Ubuntu, rebem resposta amb pèrdua de paquets zero confirmant que la xarxa està funcionant correctament entre les dues màquines de la pràctica.

    Afegim la resolució del domini Windows al fitxer hosts del client Ubuntu, afegim la línia 192.168.2.101 josep.lan perquè el sistema pugui resoldre el nom del domini directament sense necessitat de servidor DNS configurat durant les proves de connexió.

    Configurem el client DNS del Ubuntu per utilitzar el servidor Windows com a DNS principal, afegim DNS=192.168.2.101 i Domains=josep.lan al fitxer resolved.conf perquè el sistema resolgui els noms del domini correctament durant la unió al domini Active Directory.

    Reiniciem i verifiquem el servei de resolució DNS al client Ubuntu, després de configurar el DNS fem systemctl restart systemd-resolved i comprovem que estigui actiu i funcionant correctament amb la nova configuració del servidor Windows com a DNS del domini.

    Instal·lem els paquets necessaris per unir-nos al domini al client Ubuntu, executem apt install per obtenir realmd, sssd, kerberos, samba i les eines necessàries per a la integració amb l'Active Directory del servidor Windows Server.

    Continuem amb la instal·lació dels paquets de domini al Ubuntu, el sistema descarrega i prepara totes les dependències necessàries incloent llibreries de Kerberos, SSSD i Samba per a la integració completa amb l'Active Directory del servidor Windows.

    Continuem amb la instal·lació dels paquets de domini al Ubuntu, el sistema descarrega i prepara totes les dependències necessàries incloent llibreries de Kerberos, SSSD i Samba per a la integració completa amb l'Active Directory del servidor Windows.

    Iniciem el procés d'unió al domini Windows amb la comanda realm join, ens autentiquem com a Administrator del domini JOSEP.lan i el sistema comença a configurar la unió utilitzant adcli per integrar el client Ubuntu al Active Directory del servidor Windows.

    Configurem el fitxer de Kerberos krb5.conf al client Ubuntu, establim default_realm = JOSEP.LAN i altres opcions per assegurar l'autenticació correcta amb el servidor Windows i la integració amb els serveis del domini Active Directory.

    Completem la unió al domini amb èxit i configurem el keytab de Kerberos, el sistema afegeix les entrades necessàries al fitxer krb5.keytab i reinicia el servei SSSD, confirmant que el client Ubuntu ja està correctament unit al domini JOSEP.LAN del servidor Windows.

    Verifiquem l'Active Directory del servidor Windows i confirmem que el client Ubuntu apareix correctament registrat dins del domini josep.lan, específicament dins de la OU "clientsubuntu" que hem creat per organitzar els equips Linux units al domini.

    Configurem el fitxer sssd.conf del client Ubuntu per a la gestió del domini, establim el proveïdor AD, realm de Kerberos i opcions d'autenticació per permetre als usuaris del domini Windows iniciar sessió al sistema Ubuntu amb les seves credencials d'Active Directory.

    Reiniciem i verifiquem el servei SSSD al client Ubuntu, després de configurar sssd.conf fem systemctl restart sssd i comprovem que està actiu i funcionant correctament amb els mòduls per a l'autenticació d'usuaris del domini Windows.

    Configurem els perfils PAM del sistema Ubuntu per habilitar l'autenticació SSSD i crear directoris home automàticament, seleccionem les opcions necessàries perquè els usuaris del domini Windows puguin iniciar sessió correctament al client Linux amb totes les funcionalitats habilitades.

    Iniciem sessió amb un usuari del domini Windows al client Ubuntu, veiem l'indicador jpellisa@josep.lan@ubuntu9 que confirma que estem autenticats amb un compte d'Active Directory i la comanda whoami retorna l'usuari complet del domini correctament.

    Script Funcional Unio Domini client Ubuntu

    Creem un script Bash per automatitzar la unió al domini del client Ubuntu, configurem les variables IP i domini, afegim la resolució al fitxer hosts i configuram el DNS per utilitzar el servidor Windows com a servidor de resolució de noms del domini corporatiu.

    Continuem el script configurant Kerberos i sincronitzant hora amb NTP, unim el client al domini amb realm join i configurem PAM per crear directoris home automàtics per als usuaris d'Active Directory quan inicien sessió al sistema Ubuntu per primera vegada.

    Configurem SSSD i reiniciem els serveis al script, verifiquem que el client està unit al domini amb realm list i indiquem que cal reiniciar el sistema per aplicar totes les configuracions completant així l'automatització de la unió del client Ubuntu al domini Windows Server.

    Executem el script d'unió al domini i veiem el procés en temps real, el script configura hosts, DNS, Kerberos, sincronitza l'hora i comença la unió al domini amb adcli, mostrant la comunicació amb el servidor Windows i l'autenticació amb l'administrador del domini corporatiu.

    Continuem amb la unió al domini des del script, el sistema crea el compte d'ordinador ASIX2 dins del contenidor Computers d'Active Directory, utilitza keytab de Kerberos i s'autentica correctament amb el servidor Windows, completant la integració del client Ubuntu al domini corporatiu.

    El script finalitza la unió al domini amb èxit, configura el keytab de Kerberos amb les entrades necessàries, habilita i reinicia el servei SSSD, i confirma que la màquina s'ha inscrit correctament al domini JOSEP.LAN, deixant el client Ubuntu completament integrat al domini corporatiu Windows Server.

    Verifiquem el servei SSSD actiu i la configuració del domini, el client Ubuntu té tots els serveis funcionant correctament incloent SSSD amb els mòduls per a autenticació contra Active Directory, confirmant que el procés d'unió al domini s'ha completat amb èxit i el sistema està preparat per a usuaris del domini corporatiu.

    Finalitzem l'execució del script amb totes les comprovacions correctes, mostrem la configuració del domini amb realm list que indica l'estat de la unió i indiquem que cal reiniciar el sistema per aplicar totes les configuracions i completar la integració del client Ubuntu al domini corporatiu Windows Server.

    Usuari del domini iniciat sessió al client Ubuntu, veiem l'indicador jpellisa@josep.lan@ubuntu9 i whoami confirma l'autenticació com a usuari d'Active Directory, demostrant la integració exitosa del client Linux al domini corporatiu Windows Server.

    Comprovem l'Active Directory del servidor Windows i confirmem que els dos clients Ubuntu (ASIX2 i UBUNTUJP) apareixen correctament registrats dins del domini josep.lan, verificant que la unió al domini s'ha realitzat amb èxit per a tots dos equips Linux.

    INSTALACIÓ SERVEI WEB

    Instal·lem el rol de servidor web IIS al Windows Server, seleccionem "Desenvolupament d'aplicacions" dins del rol Servidor web (IIS) per obtenir totes les característiques necessàries per allotjar pàgines web i crear el lloc web de prova amb funcionalitats dinàmiques.

    Confirmem la instal·lació del servidor web IIS amb totes les característiques de desenvolupament d'aplicacions seleccionades, procedim amb la instal·lació al servidor Windows Server per poder crear i allotjar el lloc web de prova dins del domini corporatiu.

    Tenim el servidor IIS instal·lat i funcionant al Windows Server, accedim a la pàgina de benvinguda predeterminada que mostra el missatge en múltiples idiomes confirmant que el servidor web està actiu i preparat per allotjar els nostres llocs web dins del domini corporatiu.

    Creem un nou lloc web a IIS anomenat "INTRANET JOSEP PELLISA", configurem el camí físic a C:\inetpub\inntranetpellisa, port 80 i opcions d'enllaç per allotjar el lloc web corporatiu dins del servidor IIS del domini Windows.

    Creem l'arxiu index.html per al lloc web de la intranet corporativa, desenvolupem una pàgina HTML amb estils CSS que mostrarà informació de l'empresa i recursos, preparada per ser allotjada al servidor IIS del domini Windows.

    Configurem les opcions del lloc web a IIS per a l'examen de directoris, activem la visualització d'hora i extensió als llistats per millorar la navegació dels usuaris a la intranet corporativa que hem creat al servidor Windows.

    Veiem el lloc web funcionant a la intranet corporativa, la pàgina HTML que hem creat mostra correctament el títol "Intranet de Josep Pellisa" amb els recursos interns i informació de l'empresa allotjats al servidor IIS del domini Windows.

    Configurem el document predeterminat del lloc web a IIS, establim index_pellisa.htm com a fitxer principal que es carregarà automàticament quan els usuaris accedeixin a la intranet corporativa des del navegador web.

    Configurem les opcions avançades del lloc web a IIS, revisem la ruta física, protocols habilitats (només HTTP per ara) i altres configuracions del lloc "INTRANET JOSEP PELLISA" per assegurar el correcte funcionament de la intranet corporativa al servidor Windows.

    Configurem un nou registre DNS al servidor Windows per a la intranet, creem un host josep.lan amb adreça IP 192.168.2.101 perquè els usuaris puguin accedir al lloc web utilitzant el nom del domini en lloc de la IP directa.

    Confirmem la creació exitosa del registre DNS per al lloc web de la intranet, el registre host josep.lan.josep.lan s'ha creat correctament al servidor DNS del domini Windows, permetent la resolució de noms per al lloc web corporatiu.

    Verifiquem el registre DNS creat al servidor Windows, veiem l'entrada josep de tipus Host (A) amb adreça 192.168.2.101 dins de la zona josep.lan, confirmant que la resolució de noms per al lloc web funcionarà correctament dins del domini corporatiu.

    Accedim al lloc web mitjançant DNS des del navegador, la pàgina http://josep.lan carrega correctament mostrant la intranet corporativa amb tots els recursos i enllaços, confirmant que la resolució de noms del domini està funcionant perfectament amb el servidor IIS.

    El navegador ens avisa de connexió no segura al accedir a http://josep.lan, ja que estem utilitzant HTTP sense xifrat SSL/TLS, el proper pas serà crear un certificat de domini per implementar HTTPS i assegurar la comunicació amb el lloc web corporatiu.

    Seleccionem el rol de Servicios de certificats d'Active Directory al Windows Server per crear una autoritat de certificació i poder generar certificats SSL per al nostre domini, afegim també les eines d'administració necessàries per gestionar els certificats correctament.

    Seleccionem el servei de rol "Entitat de certificació" per a l'AD CS, aquesta configuració ens permetrà crear una CA interna al domini per generar i signar certificats SSL per als serveis web, incloent el nostre lloc IIS de la intranet corporativa.

    Iniciem la instal·lació dels serveis de certificats al Windows Server, el sistema comença a instal·lar les eines d'administració i el rol AD CS necessaris per configurar l'entitat de certificació del domini i poder crear certificats SSL per al lloc web.

    Configurem les credencials per als serveis de certificats del domini, utilitzem l'administrador de domini JOSEP\Administrador per configurar l'entitat de certificació empresarial amb els permisos necessaris per crear certificats SSL per als serveis del domini corporatiu.

    Seleccionem configurar només l'Entitat de certificació dins dels serveis de rol, aquesta opció ens crearà una CA empresarial al domini per signar certificats sense necessitat dels serveis web d'inscripció que instal·larem després per a la gestió de certificats.

    Seleccionem CA empresarial per a la configuració de l'entitat de certificació, aquest tipus s'integra amb Active Directory i permet gestionar certificats dins del domini, ideal per als nostres serveis web corporatius i més segur que una CA independent per al nostre entorn.

    Seleccionem CA arrel per a la nostra entitat de certificació, aquesta serà la primera CA de la jerarquia PKI del domini i emetrà certificats autosignats, ideal per al nostre entorn corporatiu on controlarem tot el cicle de vida dels certificats SSL.

    Seleccionem crear una nova clau privada per a la nostra CA arrel, aquesta opció genera un nou parell de claus criptogràfiques que s'utilitzarà per signar tots els certificats que emetrem per als serveis del domini, inclòs el certificat SSL per al lloc web IIS.

    Configurem les opcions criptogràfiques per a la CA, seleccionem proveïdor RSA amb longitud de clau 4096 bits i algorisme hash SHA256 per garantir la màxima seguretat per als certificats que generarem per al nostre domini corporatiu i el lloc web IIS.

    Definim el nom de la CA com a josep-SERVER25-CA amb el sufix distintiu del domini, aquest nom apareixerà a tots els certificats emesos i identificarà clarament l'autoritat certificadora del nostre domini corporatiu dins de la jerarquia PKI que estem configurant.

    Configurem el període de validesa de la CA a 30 anys, aquest llarg període assegura que la nostra CA arrel romandrà vàlida per a tota la infraestructura del domini, ja que el certificat de la CA ha de ser vàlid més temps que els certificats que emetrà per als serveis corporatius.

    Configurem les ubicacions de les bases de dades de la CA, utilitzem les rutes per defecte C:\WINDOWS\system32\CertLog per emmagatzemar els certificats i registres dins del servidor Windows per a una gestió centralitzada de la PKI del domini corporatiu.

    Revisem la configuració final de l'entitat de certificació abans de procedir, confirmem que serà una CA arrel independent amb clau RSA 4096, SHA256, vàlida 30 anys i ubicació correcta de bases de dades per implementar la PKI del nostre domini corporatiu.

    Hem completat la configuració de la CA amb èxit, tant l'entitat de certificació arrel com el servei web d'inscripció s'han configurat correctament al servidor Windows, ja podem començar a generar certificats SSL per al nostre lloc web IIS del domini corporatiu.

    Tenim els nous llocs web de certificats creats automàticament a IIS, veiem CertEnroll i CertSrv que són les pàgines web per a la gestió i inscripció de certificats, juntament amb el nostre lloc INTRANET JOSEP PELLISA que necessitarà certificat SSL.

    Accedim al lloc web de certificats del nostre domini, la pàgina CertSrv permet sol·licitar, revisar i descarregar certificats de la CA corporativa, incloent certificats SSL per al nostre lloc web IIS que necessita HTTPS segur.

    Seleccionem sol·licitar un certificat avançat per al lloc web, necessitem una petició específica de certificat SSL per a servidors web amb opcions personalitzades per a la intranet del nostre domini corporatiu i el nom del servidor IIS.

    Configurem l'enllaç HTTPS al lloc web IIS, seleccionem el port 443 i assignem el certificat de la nostra CA corporativa josep-SERVER25-CA per habilitar SSL/TLS al lloc de la intranet i proporcionar connexions segures HTTPS als usuaris del domini.

    El navegador mostra error de certificat per a localhost, ja que el certificat està emès per a un nom diferent (el nom del domini) i no per localhost, necessitarem sol·licitar un certificat específic per al lloc web de la intranet amb el nom correcte o utilitzar el nom del domini per accedir.

    Compliquem la informació per al certificat del lloc web, introduïm les dades del domini i servidor per generar un certificat SSL específic per a la intranet corporativa que s'integrarà correctament amb IIS i evitarà els errors de seguretat al navegador.

    Obtenim un error al sol·licitar el certificat amb el formulari web, probablement degut a problemes de configuració del servidor de certificats, necessitarem utilitzar una altra via com el snap-in de certificats de Windows o sol·licitar via PowerShell per obtenir el certificat SSL per al lloc web IIS.

    Descarreguem el certificat de la CA en format Base64 per instal·lar-lo als clients i navegadors, així els sistemes confiaran en els certificats emesos per la nostra CA corporativa i no mostraran errors quan accedeixin al lloc web HTTPS de la intranet.

    Veiem la informació del certificat de la CA descarregat, confirmem que està emès i signat per si mateix (autosignat) i vàlid per 30 anys, ara podem instal·lar aquest certificat al magatzem de autoritats de confiança perquè els sistemes acceptin els certificats que emeti la nostra CA corporativa.

    Importem el certificat de la CA al magatzem de certificats del sistema, seleccionem l'opció automàtica perquè Windows instal·li el certificat arrel al magatzem d'Autoritats de certificació arrel de confiança, permetent que tots els certificats emesos per la nostra CA siguin confiables als clients.

    Completem la importació del certificat CA amb èxit, el certificat arrel de la nostra CA corporativa ara està instal·lat al magatzem d'autoritats de confiança del sistema, permetent que els certificats SSL emesos per aquesta CA siguin acceptats sense errors pels navegadors i clients del domini.

    Configurem l'enllaç HTTPS per al lloc web amb IP 192.168.2.101, port 443 i nom de host josep.lan, seleccionem el certificat de la nostra CA per habilitar SSL/TLS i proporcionar accés segur HTTPS al lloc de la intranet corporativa per als usuaris del domini.

    Configurem les opcions SSL del lloc web a IIS, seleccionem "Requerir SSL" per forçar connexions HTTPS i "Acceptar" certificats de client per permetre autenticació opcional, assegurant que tot el tràfic cap a la intranet corporativa estigui xifrat i segur dins del domini.

    Veiem el certificat del servidor web instal·lat correctament, el certificat emès per josep-SERVER25-CA està disponible al magatzem personal del servidor IIS i preparat per ser utilitzat amb SSL/TLS al lloc web de la intranet corporativa del domini.

    Solució Error Certificat de Domini AD

    Instal·lem la funció de CA amb PowerShell per solucionar els problemes de certificats del domini, executem Install-WindowsFeature Adcs-Cert-Authority -IncludeManagementTools i confirmem que s'instal·la correctament sense necessitat de reinici, preparant el servidor per gestionar certificats de domini per a l'Active Directory.

    Has raó, així sona més natural en català:

    Arrenquem el servei CertSvc. Primer comprovem el seu estat i veiem que està aturat. Després l’engegem i tornem a comprovar per confirmar que ara està en execució.

    A la finestra de "Propiedades de Servidor web" podem veure els permisos de seguretat per a diferents comptes d'usuari i grups. S'hi llisten comptes com l'Administrador, els administradors del domini i els usuaris autenticats. Des de aquí és possible afegir, eliminar o modificar els permisos d'accés assignats.

    Aquesta finestra s'anomena "Agregar o quitar complementos" i forma part de la Consola d'Administració de Microsoft (MMC). En aquest cas, estem configurant una consola personalitzada per gestionar certificats.

    A la llista de "Complementos disponibles" podem veure diversos snap-ins que es poden afegir, com ara Certificats, DNS, Editor ADSI, etc. A la dreta, a la secció "Complementos seleccionados", veiem que actualment la consola només té la "Raíz de consola" i el snap-in de "Certificats (equipo local)".

    Generem una nova plantilla a traves de un clonatje del Servei Web i afegim als usuaris pertinents i amb la caracteristica clau de SAN.

    Creem un fitxer .inf amb els paràmetres de sol·licitud de certificat. Especifica el nom del subjecte (josep.lan), la longitud de la clau (2048 bits), el tipus de sol·licitud PKCS10 i la plantilla "WEBSERVER-SAN". També inclou l'extensió per a noms alternatius (SAN) amb el DNS josep.lan.

    Amb el comando certreq -new generem una sol·licitud de certificat a partir del fitxer .inf. El sistema crea el fitxer de petició .req i utilitza la directiva d'inscripció d'Active Directory amb el GUID mostrat. Això permet preparar la petició per signar-la per l'autoritat certificadora.

    En aquesta captura es mostra la llista d'entitats certificadores (CA) disponibles, on seleccionem josep-SERVER25-CA. Després, amb el comandament certreq -submit, enviem la sol·licitud guardada al fitxer .req a aquesta CA per obtenir el certificat signat, que es desarà com a web_pellisa.cert.

    A la consola de l'entitat certificadora (CA), dins de "Certificats emesos", podem veure la sol·licitud d'ID 9 feta per JOSEP\Administrador. S'ha emès utilitzant la plantilla WEBSERVER-SAN. Això confirma que el certificat ha estat generat i signat correctament.

    Amb el comandament certreq -retrieve 9 recuperem el certificat emès amb l'ID de sol·licitud 9 i el desem a web_pellisa.cer. El sistema confirma que el certificat ha estat "Emitit" i recuperat correctament per a l'usuari JOSEP\Administrador.

    Amb certreq -accept instal·lem el certificat recuperat al magatzem local. El certificat és per a CN=josep.lan amb SAN inclòs, vàlid des de l'1/2026 fins al 1/2027. La empremta digital és 8fb12... i el número de sèrie es mostra.

    A la consola de certificats, dins de "Certificats (equip local) > Personal", podem veure que el certificat per a josep.lan emès per josep-SERVER25-CA s'ha instal·lat correctament. Això permet al sistema utilitzar-lo per a autenticació o xifratge.

    A la finestra "Modificar enllaç de lloc" estem configurant un lloc web per a HTTPS. Especifiquem l'adreça IP 192.168.2.101 i el port 443. Seleccionem el certificat josep.lan per a SSL, el mateix que acabem d'instal·lar. Això permet que el servidor ofereixi connexions segures.

    Finalment comprovem desde un client unit al domini com podem accedir al servei web via https, per el port 443 i obtenim certificats de domini correctament coonfigurats.

    Aqui observem com la intranet del nostre servidor ja esta segura amb els certificats corresponents.
